# MTG Collection — project rules for Claude

## What this is
A Magic: The Gathering collection and deck tracker, shipped as TWO versions from ONE repository:

1. **Web version (PWA)** — hosted on GitHub Pages. Used by everyone, including iPhone users. Starts empty; each person's data lives only in their own browser storage. Never ships the owner's personal collection.
2. **Android app (APK)** — built from the same web code wrapped with Capacitor. Ships EMPTY like the web version (no personal data inside the APK). The owner loads their collection once by restoring a backup file (More → Backup). Can use native Android capabilities.

## The parity rule (important — the owner asked for this explicitly)
- The two versions have DIFFERENT capabilities. For every feature or change, always think about both versions and offer a solution for each.
- They do not need to be identical. The Android version is expected to be more robust (e.g. live database file on the phone, automatic backups, better camera/OCR, file access).
- Do NOT let them drift far apart. Keep one shared codebase for everything that can be shared, and put platform-specific behavior behind a small platform layer (`isNative()` checks), not in forked copies.
- If a change cannot be shared or worked around, STOP and ask the owner for explicit approval before making the versions diverge. Say what each version will do differently and why.
- One push updates both: the web site and the APK are built and published together by the same GitHub Actions run.

## Working agreements
- Never push to GitHub without the owner's approval of the change first.
- Never commit the owner's personal collection data anywhere in the repo or the APK. Their data is loaded only by restoring their own backup file; keep the backup format (.sqlite/.json) restorable on both versions.
- The owner's real data lives on their phone. Updates must never overwrite or reset existing user data (storage keys stay stable; the app only ever starts empty or from a restored backup).
- The owner is not very familiar with GitHub: explain steps plainly and carefully.
- Existing app behaviors to preserve: deck edits are staged (+/−/add) and only applied by “Save changes” with a confirmation, followed by a pull-list popup grouped by set source or deck, verified-artwork gold checkmark, source dropdown with "add new", sleeve palette/photo crop, AI deck builder (Option A copy/paste, Option B own API key — saved on the device it was typed on, per provider, in its own storage key `mtg_aikeys_v1` outside the collection data; never in share files; manual backups and device transfers ask before including keys, automatic backups always include them; restores only adopt keys for the same collection ID or an empty app and never overwrite a key already saved; “Remember my API key” can be switched off), backup to share sheet / .sqlite / .json.

## Build & release
- Web: GitHub Pages serves the repo root (index.html, sw.js, manifest, icons). Android: `.github/workflows/android.yml` wraps the same files with Capacitor (appId com.dakeera.mtgdeckmaster, name "MtG DeckMaster") and publishes a signed APK to Releases on every push to main.
- The APK must always be signed with the same key (GitHub secrets ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS) so updates install over the old app and keep the user's data. Never change the appId or the key.
- Manual backups: when a key is saved, “Back up” first asks Yes (include API keys) / No (leave them out) / Cancel (no backup) (`doBackup(share,keys)`). “📂 Open my backups folder” (`fxOpenBkFolder`): Android calls the native `ApkUpdater.openFolder` (opens the phone’s file manager at Documents/MtG-DeckMaster, falls back to another file manager or a how-to); the web version can’t open folders, so it explains where the browser saved them (Downloads / where the share sheet put them) — an owner-approved platform difference.
- Auto-backup (More → Backup, off by default): newest 5 JSON copies; Android writes files to Documents/MtG-DeckMaster/autosave, web keeps them in IndexedDB. Never touches manual backups.
- Back button: one shared `navBack()` in index.html (modals → in-tab steps → tab history → double-back to exit). Android hooks it to `@capacitor/app`; the web version uses a history sentinel.
- In-app updates (Android): `android-resources/native/` holds a local Capacitor plugin `ApkUpdaterPlugin.java`, a `MainActivity.java` that registers it, and `file_paths.xml`; the workflow copies them into the generated android project and adds `REQUEST_INSTALL_PACKAGES`. The app checks GitHub Releases (`android-v1.N` tags) at most once per 20 h and from More → App updates, downloads the APK into its cache, then opens Android's installer (the user must tap Install; first time also allow “Install unknown apps”). Web version: compares a hash of the live `index.html` + `features.js` with the loaded one and shows a Reload banner. Both banners offer a non-blocking “Back up now”.
- Android-only code goes behind `window.Capacitor?.isNativePlatform()`. The shared code is `index.html` (core app) plus `features.js` (deck draft editing, in-app camera, bulk import, other people's collections viewer, formats guide, battle simulator); both versions load the same two files. A new shared file must also be added to `scripts/build-www.js` and the `SHELL` list in `sw.js`.
- Identity: each collection has a permanent random ID (`D.uid`, shown as a short code), a changeable name (`D.owner`) and an ECDSA signing key (`D.keys`). No server or user database. IDs are only created by “Start my collection” or the first save, never changed by renaming, and restored with a backup. File names start with name + ID code.
- Two file kinds: full **backups** (private; include `D.keys`) and signed **share files** (`kind:'mtg-share'`; cards and decks only, never keys, logs, sleeves or acquisition data). Every file goes through `fxOpenFile`, which decides restore vs view and warns on other people's backups, older backups, changed files and signature mismatches (with trust / keep-both options). Never put `D.keys.priv` in anything that is shared or stored under Other collections.
- Deck links (`…/d/#d=…`) carry deck names only and are unsigned; they open view-only. `d/index.html` is the web landing page (tries the Android app via an `intent://` link, then falls back to the web version). The APK registers the `mtgdeckmaster://` scheme and the `https://dakeera.github.io/mtg-collection/d` App Link (workflow `sed` on AndroidManifest); fully automatic opening needs `android-resources/assetlinks.json` published at `https://dakeera.github.io/.well-known/assetlinks.json` (a separate `dakeera.github.io` repo).
- The fourth tab is called “Deck Generator” (internal view key is still `ai`). Deck types come from `DFMT` in features.js (Casual + official constructed formats + MTG Arena formats + community formats; Draft, Sealed, Cube, Jumpstart and Two-Headed Giant are deliberately excluded). The user must pick one (“↺ Start over” clears every option after a confirmation); commander suggestions use the same availability/legality/color filters as the card list (`aiCmdChoices`); its size, copy limit, commander rule and legality key drive the prompt, the reply check, deck targets and sleeves. Decks can also be built by hand: New deck → card picker (`fxBuilder`) → staged Save. Every deck format has rules built in: staged adds are blocked once the deck reaches the format size; banned / not-legal / restricted / too-many-copies / outside-commander-colors cards (color identity from `fxCI`: Scryfall `c.ci` when known, else every colored mana symbol in cost + rules text — never just the `colors` text, which can say e.g. “Colorless/Multi”) can still be added but are flagged (`fxCardIssues`, `deckIssues`), shown with ⚠ on the Decks list and an Inspect box on the deck page with staged fixes or “Ignore this” (`d.ok`; ignored issues stay listed, muted, with “Stop ignoring”). Formats with a legality key pause for a legality check (`ensureLegal(list)`) when a deck is opened or the picker starts; if offline the deck gets `d.legPending` (⏳ on the Decks list, “Check now” on the deck page), re-checked whenever the deck is opened, cleared once it succeeds. Cards Scryfall can’t match get `legMiss` (plus a fuzzy-match suggestion in `legSug`); the user can accept the suggestion, search (`fxMatchUnknown` — updates the EXISTING card via `renameCard`, never a duplicate) or mark it as a custom card (also creatable from scratch with “★ Add a custom card” on the Add card tab, `fxCustomNew`, and editable later with “✎ Edit card details”, `fxCustomEdit`; custom cards have no Printing row) (`c.custom`: its own group in the Collection filter, CUSTOM badge, skipped by all Scryfall lookups and data check, flagged as not legal in official formats, kept in share files). Opening a modal from another tab (e.g. “Build a deck by hand” on Deck Generator, multi-card add on Add card) must not switch tabs until something is actually created.
- ✨ Optimize Deck (deck page, next to “＋ Add cards”; Edit details / Share deck / Delete deck sit on the row below; Delete deck asks twice, the second time “Are you sure???”): `fxOptOpen` → `V.opt` view (`fxOptView`, state `OPT`) with the Deck Generator’s tools (legality for casual decks, colors — commander identity for commander decks, else the deck’s current colors unless the user picks colors —, where new cards may come from, only-own, Option A copy prompt, Option B shared provider/model/key via `aiKeyUI()`). The “How do you want to optimize?” goal works like Theme; blank = review the collection + deck for a more optimal build. The AI answers with `OUT n Card` / `IN n Card` lines + `---` + explanation; `fxOptRead` checks every line against the deck’s format rules (`fxRuleBlock`, copy caps, size, availability, commander stays). “Accept” shows a confirmation screen (removals on top grouped by where they go back to, additions below grouped by pull source/“From deck”), and “Update deck” applies it through the staged-draft save (`fxDraftSave({yes,allowed})`) followed by the usual pull list. The Deck Generator uses the same rule check (`fxRuleBlock` + size cap, commander color identity in the prompt) and the same grouped confirmation (`aiConfirm`) before creating a deck.
- Pop-ups: while any modal/full-screen layer is open the page behind can’t scroll (`fxLockCheck` toggles `html.lock`).
- Confirmations: never use the browser's `confirm()`/`prompt()` (plain, inconsistent on Android). Use `await ask(msg)` → true/false and `await askText(msg, default)` → string/null (index.html, `#askov` window above every other layer, same on web and Android). Lines “OK = …” / “Cancel = …” in the message become the button labels; a short first paragraph becomes the title; a leading verb (Delete, Add, Save…) labels the OK button; destructive wording makes it red. The back button / Escape / tapping outside cancel. Functions that ask are `async`; keep the question before the first change so nothing happens on Cancel. `navBack()` stays synchronous (uses `ask().then`).
- Wording: the user-facing name for a card's source is “Pulled from” (dropdowns, imports, Data check, confirmations); the WotC set is “Printing”.
- Tab icons (owner’s choice): Collection = icons/nav-collection.png (owner’s own image), Decks = nav-decks.svg (card stack), Add card = nav-add.svg (card + green plus), Deck Generator = nav-generate-orb.svg (crystal ball), More = nav-more.svg (spellbook); all listed in sw.js SHELL and build-www.js.
- Look & layout: slim backup strip (`.bkstrip`), Collection stat line + “⚙ Filter & sort” window (`fxFilterPop`: type/color chips with counts, sort, “Show N cards”; active filters shown as removable chips under the search), legality shows “Legal in” with the rest under “Show all formats”, Deck Generator/Optimize Option A and B fold away (`details.aopt`, last-used one opens, `mtg_aiopt_v1`), More is grouped (My stuff / Tools / History / Other people) with “‹ All options” and the back button returning to the groups, Decks list has search (`V.dq`), a color strip (`fxDeckStrip`) and a commander/main-card picture (`fxDeckThumb`), cards without a picture get a color-tinted card frame (`fxPh`). Toasts sit above the tab bar, scale their time to the text and close on tap. Remembered per device: last “Pulled from” for single add (`mtg_lastsrc_v1`), backup file type (`mtg_bkf_v1`), Deck Generator choices (`mtg_gen_v1`, cleared by ↺ Start over). “Erase everything on this device” asks twice.
- Deck links: “Share as a link” makes a TinyURL short link (`fxShortUrl`: Android via CapacitorHttp, web via fetch, is.gd JSONP as web fallback) to `…/d/?d=<compact code>` (`fxPackDeck`, prefix `c`: `#set:number` for cards with a known printing, names otherwise, qty 1 omitted). The app-only link (`fxAppLink`, `…/d/#d=<code>`) is offered only when offline (checked at link time) or, when online, after TinyURL failed twice (first failure: Try again / Send as a file; second: app-only link / Send as a file; resets each time Share deck is opened). Pasted tinyurl/is.gd links are resolved on both versions (`fxOpenShort`; is.gd via its forward JSONP `fxIsgdLookup`, TinyURL via CapacitorHttp on Android, else by opening the link). Old `j`/`z` links still open. Compact links are signed with the collection key (`k:` public key + `s:` signature lines). On opening (`fxLinkImport`): a verified link joins that sender’s entry in Other collections (grouped by sender, same entry as their signed share files); an unsigned/altered link goes into a separate unverified “— shared by link” entry; a key clash with a known sender asks first and stays separate; a link signed with the user’s own key is treated as their own deck (opened, or offered to add if missing). Other people’s decks are shown as “Owner - Deck” (`fxDeckTitle`) on their deck pages, in Matchups and in share messages; Other collections rows list each sender’s decks.
- Build a shared deck (Other collections → open a deck → “🛠 Build this deck with my cards”, replaces the old Copy button): `fxBuildPlan` leaves the view-only collection and checks every card against the user’s own collection — free copies are used, copies in the user’s other decks are either borrowed (loan, red ★) or left as missing, cards not owned are marked 🛒 missing (with TCGplayer search links). `fxBuildMake` creates “Owner - Deck” with the full list; missing copies live in `d.miss` [{name,qty,why:'buy'|'deck',deck,st:'missing'|'ordered',od}] and are subtracted in `usage()` so they never use up the collection. Deck page box `fxMissBox`: TCGplayer link, “Ordered” (confirm), then “Order cancelled” (back to missing) or “Card received” (confirm → Scryfall lookup → `fxAddCard` under “Singles Orders” → offers artwork verification); also “Borrow from …”, “Use my free copy”, “Buy all on TCGplayer” (mass entry) and “Mark all as ordered”. Decks list shows 🛒/📦 counts; deck edits clamp `d.miss`. Missing cards show an estimated cost (Scryfall market price, `m.usd` from the sender's data or the user's own card); “Ordered” takes an optional note (`m.note`, store/order number); “Card received” asks how many arrived when more than one is on order (the rest stay ordered). Cards added later through Add card make “Use my free copy” appear.
- Building a deck by hand (`fxBuilder`): “Only add cards that are in my collection” (checked by default). Unchecked, the search also looks on Scryfall (`fxBScry`, 3+ letters) for cards the user doesn’t own; “＋ Add” (`fxBNew`, with copies) asks for confirmation, adds them to the collection under the source typed in “New cards are pulled from” (new names auto-numbered once and reused for the session) and stages them into the deck. Pulling a card you own (+) also asks first; both stay staged until “Save changes”.
- Deck viewer filter (`V.df`, reset when another deck is opened): tap a card-type tag or a mana-curve bar to filter the deck’s cards (tap again to remove); “🔍 Search deck” (`fxDeckFind`) searches name/type/rules text with type, mana value and color (incl. colorless) chips and lists matches; “Show on the deck page” keeps the filter, “✕ Clear filter” removes it. Read-only — works on other people’s decks too.
- Rule override: adding a card that breaks the deck's format rules (including going over the card limit) is blocked unless the deck is in override mode; turning it on takes two confirmations in a row (`fxOverrideAsk`), once per deck (`d.override`). An overridden deck always shows a red “⛔ Override on” tag on the Decks list and a box on the deck page that open the full list of violations; it can be turned off, and it switches itself off automatically (`fxOverrideAuto`) once the deck has no rule issues left, so breaking a rule again needs two approvals again.
- Custom card photos: the 🎨 button on a custom card opens `fxCustomArt` (take a photo with the framed in-app camera, or upload a picture) — never the printing picker, Scryfall search or card scan (`artPicker`/verify redirect custom cards there). Pictures are compressed to ~60 KB JPEG (490×684), kept in IndexedDB (`mtg_imgs`, in memory as `CIMG`), never in localStorage. They are added to backups, auto-backups, device transfers and share files as `customImgs` (`fxWithImgs`) and read back with `fxImgsIn`.
- Card page checkmark/🎨 buttons sit just outside the picture frame's top corners (`.frame .vfbtn/.artbtn`, z-index above the foil shine); foil frames keep `overflow:visible` (`.frame.foil`) so they are never cut off.
- Foil: Scryfall images are non-foil scans, so finishes are shown with labels on artwork choices (`fxFinLabel`) and a ✦ FOIL tag plus rainbow shine on cards owned as foil (`fxHasFoil`).
- Suggestion lists: never rely on the browser's `<datalist>` popup (Android draws it see-through in dark mode). Any `<input list=…>` is converted automatically to the styled `.acbox` dropdown (`fxACWire`), so new suggestion lists can still be written as `<datalist>`. The list scrolls with a finger; an option is chosen only by a deliberate tap (pointer down and up on the same option without moving). Suggestion fields and search boxes inside pop-ups get a ✕ clear button (`.acw`/`.acx`) once they have text.
- The source “Custom Cards” is reserved: every custom card is filed under it (`CUSTOM_SRC`), it is never offered or accepted as a source for real cards (`isCustomSrc`), and it is never auto-numbered. “It’s a real card — unmark” asks for approval, then for an existing or new source (`fxUnmarkCustom`), which replaces Custom Cards on the card and its acquisition entries.
- “Add several cards at once” (Add card tab): after lookup, cards go through a card-by-card picker in the typed order (`fxQAPick`: choose the printing/artwork, finish and copies; misspelled names are matched with Scryfall’s fuzzy lookup and flagged “you typed …” with “Not right? Search again”; still-unknown names show “Did you mean” suggestions and can be searched again, scanned, or skipped), then the usual review and confirmation; the card name + copies/finish bar sticks to the top (`.qabar`) and Previous/Skip/Next stays fixed above the tab bar (`.qanav`) while the artwork scrolls. Tapping the set text under an artwork just selects it (highlight, stays on the screen, keeps the scroll position); tapping the picture opens it full screen (`fxQAView`, `#qafull`: ‹ › arrows and swipe through every printing, ↻ Flip for double-faced cards, “Use this one” / “Back to list”; the back button closes it first). The typed text is kept (`V.qadd`) until the cards are added, and the box has a ✕. “⏭ Skip artwork for the rest” (`fxQASkipArt`, asks first) jumps to the review: the current and remaining cards keep Scryfall’s matched printing and are added unverified (`x.nover`), not-found names are left out. Single add: “⏭ Skip the artwork check” on the artwork step (`fxSkipArt1`, asks first; `A.skipArt` also stops auto-matching) adds the card unverified; once a printing is chosen an “Estimated value” box (`fxAddVal`: Scryfall price for the chosen finish × quantity) shows on the artwork and questions steps.
- Bulk imports (More → Bulk import and “Add several cards at once”) are always ONE source: the card’s set comes from the chosen printing, and the source is asked on the final check screen with the same picker as a single add (`srcFields`; `SQ()` returns `IMP.sq` while that screen is showing, else `A.q`). Nothing is added until a source is chosen; a file’s own Source column is not used. Cards whose printing was picked in the several-cards picker are added as verified ✓ (`fxAddCard(…,ver)`; an already-verified artwork is never replaced, and the picker preselects it). The WotC set/printing is stored on every card but only shown (card detail “Printing” row) once the artwork is verified.
- Several copies of a card (`fxCopiesOn`: real, not custom, not basic, qty > 1): tapping the artwork on the card page opens “Your N copies” (`fxCopiesOpen`) — a tile per copy, its verified artwork or a card-shaped “?” box; tapping a copy opens the printing picker for that copy (`artPicker(name,k)`, `useArt` → `fxCopySet` with confirmation). Copy 1 is the card’s own printing (`set/cn/scryId/verified`), copies 2+ live in `c.cps[k-1]` ({set,setName,cn,scryId,art,art2} or null); only the first `qty` copies are shown. The Printing row says “x of N copies verified”. Adding several copies at once: `fxSetCopies(card,printing,n)` gives n not-yet-verified copies a printing (copy 1 first, then `c.cps`, never replacing verified ones). The several-cards picker starts with the full count; lowering “Copies” (`fxQAQty`) brings the same card up again for the rest (`fxQASplit`, `restOf`). Single add with a chosen printing and quantity > 1 has “All N copies have this artwork” (untick → adds one copy with it, then opens the copies screen). Import-history verification has “Copies with this artwork” and brings the card back for the rest. “Card received” with several copies opens the copies screen. Values: each verified copy carries its own Scryfall price (`cps[k].price`, refreshed with the weekly price update); `fxCopyVals` prices every copy by its own printing (unverified copies use the card’s price, finishes handed out in order), `fxVal` (collection total, sorting, deck value) uses it, and the card page lists “Value per copy” with a “Total value of all N copies” line. Checkmarks (`fxVerState`): gold ✓ = every copy verified, silver ✓ = only some, none → 🎨 (tiles and the card page button; tapping a ✓ with several copies opens the copies screen). Basic lands (`fxBasic`) never need verified artwork: no Printing row, no ✓, never shown as foil, skipped by Data check “Resolve missing artwork”, import-history and pull-source verification — but their copies screen still lets the user pick artwork per copy.
- Copies screen: when copy 1 is verified and other copies aren’t, “Use copy 1’s artwork for the N unverified copies” (`fxCopiesSame`, asks first, logged) fills only the unverified ones. History → Edits has a search box (`V.eq`, `edList`/`edDraw`; matches date, card, field, old and new value).
- Artwork picker (`artPicker`, card page 🎨 / a copy on the copies screen) works like the several-cards picker: tapping the set name under a picture selects it (gold outline, `AP.sel`), tapping the picture opens the shared full-screen viewer (`fxPrintView`, same as `fxQAView`: ‹ ›/swipe, ↻ Flip, “Use this one” = select), and the sticky bar “Use this artwork” (`#apbar`) saves the selection through `useArt` (with its confirmation).
- Where cards are stored (owner rule): each WotC set is its own physical place; every other “Pulled from” (Bulk Box 1, Singles Orders, Trade, Gift and any custom source added later) shares ONE storage, “Bulk & singles” (`fxStoreLabel`: Scryfall set name via `fxSetIn` when the set list is loaded (cached `mtg_sets_v1`, loaded at start), else WotC product words in the name (`FXPRODRE`, e.g. a precon typed by deck name stays its own place); `fxCardLabel` uses it for every pull list / “goes back to” label).
- Deck source tracking: every collection copy in a deck is assigned to a “Pulled from” — `d.srcs = {normName:{source:qty}}`, kept up to date by `fxAllocAll()` on every `save()` (keeps existing choices, trims removed copies from the last-assigned source, never hands out more than a source holds (`fxSrcOwned` from `D.acq` + card sources), fills new copies from the source with the most free copies). Borrowed copies (loans) and missing copies (`d.miss`) aren't allocated. Pull lists after Save changes / Deck Generator / building a shared deck come from the allocation diff (`fxAllocDiff`): grouped by storage, each line says “(pulled from <source>)”. The card page “Pulled from” box (`fxSrcBox`) lists each source with its storage, copies, which decks use them and how many are free; “In decks” shows per deck which sources (and borrowed copies) it uses. Tidy-up renames also rename `d.srcs` keys.
- Verified artwork: every way a printing gets confirmed goes through `fxVerifyPrint` (sets printing + `verified:true` = gold ✓, logs the edit, refreshes price/art): artwork picker/scan (`useArt`), single add, several-cards picker, import-history verification, pull-source verification.
- Data check → “🎨 Resolve missing artwork” (`fxMissArtView`): every real, non-custom, non-basic card with an unverified copy, grouped by pull source (`fxMissArt`; a card with several sources is listed under each, “also from …”). “Start” on a source opens the same verify picker (`fxMissArtGo` → `IMP.kind='verify'`, `IMP.vsrc`, header “Pulled from: …”; copies default to how many came from that source per `D.acq`). When a card has copies from other groups, verifying one group only covers that group's copies — it isn't brought up again for the rest (`x.cap`). Progress saves card by card; “Finish later” / Back on the first card returns to Data check with the list reopened.
- Import history (`D.imports`, newest first; shown on More → Bulk import): every bulk / several-cards import is recorded (date, source, cards, chosen printing id). After a bulk import the app asks whether to verify artwork now; verification (`fxHistVerify` → `IMP.kind='verify'`, `fxVerPick`) saves each card as you go (“Save & next”, “Skip for now”, “Finish later”), so it can be partly done and resumed. Cards verified any other way count as done. Removing an entry never touches the cards.
- Only one printing (owner's choice): a card with exactly one paper printing on Scryfall (`fxPaper`: not digital-only) needs no artwork check — single add selects it automatically, `fxSrcVerify` verifies every unverified copy of such cards (`fxOneApply`, also cards with some verified copies), and bulk / several-cards imports run `fxOneCheck` on the added cards afterwards. Logged as “only one printing exists”.
- Pull-source verification (`fxSrcVerify`, runs once automatically when online — `D.srcv4` (was `srcv3`; bumped so the one-printing rule runs once on existing collections) — and again after a restore if not done; button on More → Data check): a card whose every pull source resolves to exactly one printing gets ALL its copies verified. A source's WotC set (`fxSetFor`) comes from the Scryfall set list (`fxSets`, cached 7 days in `mtg_sets_v1`, device-only): longest official name or short form found in the text (`fxSetIn`, e.g. “Duskmourn Commander” = “Duskmourn: House of Horror Commander”; a commander-deck source moves to its set's Commander child set); if none, the one set that contains ALL of that source's cards (`fxSrcInfer`, ≥3 cards — catches precons typed by deck name only). Booster sources keep only booster printings; commander sources keep only the regular precon printing (`fxPreconPrint`: no thick display commander, extended/showcase/borderless/promo variants). Anything uncertain (several printings, Trade/Gift/Singles or non-set sources, mixed sources) stays unverified and is listed with the reason. OWNER RULE: it only ever touches cards with NO verified copy at all (`fxCopyList(c).some(Boolean)` → skipped; `fxVerifyPrint` refuses “Pulled from” verifications on such cards too) and never cards marked `c.noAuto`; the all-cards inference (`fxSrcInfer`) is only for commander-deck sources and only returns a Commander set, so custom sources like “Mystery Box 1” are never matched. `fxAddCard` never replaces a verified copy 1 printing when more copies are added.
- Scryfall limits (https://scryfall.com/docs/api/rate-limits), in `scryGap`/`scryFetch`/`scry` (index.html): one queue for every call; search/named/random/collection ≥550 ms apart, others ≥110 ms; a 429 — or a network error while online, because a 429 often arrives without CORS headers — pauses ALL calls 5 s (owner's choice; toast tells the user) then retries, up to 6 times so a 30 s lock-out is still ridden out. On-device Scryfall cache (owner's request): every GET lookup through `scry()` is stored per request URL in IndexedDB `mtg_scry` (store `r` {u,j,t,a,n}, size total in store `m`) for 7 days (`SCRY_TTL`), max 200 MB (`SCRY_MAX`; `scryTrim` drops least-recently-used down to 90%); a stale entry is returned when Scryfall can't be reached (offline/429/5xx); 404s aren't cached; `/cards/random` and the price POST (`/cards/collection`) are never cached; also a 400-entry memory map `SCRYC`. Never in backups/share files; Data check shows its size with “Clear saved lookups” (`fxCacheView`/`fxCacheClear`). Works the same on web and Android (both IndexedDB).
- Tidy up “Pulled from” names (Data check, `fxTidyScan` → review `fxTidyOpen` → `fxTidyApply`, asks first): suggests the official WotC set name for every source using the same set matching, keeping the user's number exactly (`fxTidyName`: “<Set> <Product> <number>”; commander decks “<Set> Commander Deck – <deck name> <number>”). Each row can be unticked, the set picked/changed, or the new name edited; sources with no set are listed separately (pick a set or leave them). A name that would join an existing one starts unticked with a warning. Renames update cards (logged as edits), `D.acq`, import history and the remembered last source, then the artwork verification runs again.
- New manually typed sources are auto-numbered (“Mystery Box” → “Mystery Box 1”, next pull “… 2”); Trade, Gift and Singles Orders are never numbered.
- Other people's collections are view-only: while one is open (`RO` set) `persist()`/`save()`/`saveArt()` do nothing, so the owner's own data can never be overwritten. Keep that guard.
- Approvals (owner rule): every user action that changes a card, its details, its place (deck, loans, sources) or any other saved data asks for confirmation first — single add, put in deck, new deck, sleeves, rename collection, deck details, custom card mark/photo, ignore/stop ignoring issues, data-check “keep”, simulations and their notes, building a shared deck, import-history “Save & next”, missing/ordered/received; the automatic pull-source verification is the exception the owner chose: it applies on its own only when a source points to exactly one printing, everything uncertain waits for the user. Steps that already had a confirmation, a review screen with an explicit final button, or a double approval stay as they are. Background data refreshes (legality, prices, artwork) and override auto-off are not user changes.
- When a scan or printing change reveals that an existing entry's data is wrong, the app asks for approval and UPDATES THE EXISTING CARD. It must never create a duplicate card for that.
- Abilities explained: the card page shows an “Abilities explained” box under Rules (`fxKwBox`, glossary `FXKW` in features.js — plain-language summaries in our own words) with one bullet per keyword ability/action found in `c.keywords` or the rules text (reminder text in brackets ignored; generic words like Tap/Exile/Sacrifice only when they're real keywords). No keywords → no box.
- Values count verified artwork only: `fxVal` (collection stat line, More → profile “Estimated value”, deck value, card-page totals) adds only copies whose artwork is verified (basic lands always count; `fxCopyVals(...).cnt`). Unverified copies still show their price on the card page in brackets with “not counted until its artwork is verified”. Sorting by price and the price badges on tiles use the full market value (`fxValAll`/`fxEachAll`).
